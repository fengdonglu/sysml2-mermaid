# Design: v0.6 — View/viewpoint selection syntax

English only.

## Status

Approved for implementation planning. Builds on v0.5. Adds a real (small)
`view` / `viewpoint` subset that selects **which elements** a diagram shows, plus
the `abstract` prefix and metadata annotations (`#Name`) that `filter` needs.

## 1. Scope

1. **view/viewpoint constructs** — `viewpoint def`, `view def`, `view`,
   `viewpoint`, with `expose`, `filter`, and `render` members.
2. **Metadata annotations** — `#Name` before a definition/usage, and `@Name;`
   inside a body, so `filter @Name` is meaningful.
3. **`abstract` prefix** on definitions/usages (`isAbstract`).
4. **Diagram-kind selection** by the view definition's standard base, and
   **element scoping** from `expose` / `filter`, selectable from the library and
   the CLI (`--view-name`).

### Out of scope (deferred to v0.7+)

- Structural constructs: `connection def` / `interface def` / `end`, `item`,
  `alias`, `allocate`, port direction prefixes.
- Evaluation of `filter` expressions beyond `@Name` conjunctions with `and`.
- `frame` / `concern` / `stakeholder` semantics, `satisfy <viewpoint>` checks.
- Sequence / geometry / grid / browser views; expression and constraint solvers.

## 2. Parser additions

Verified against the SysML v2 textual BNF (Clause 8.2.2.26) and training models.

```sysml
viewpoint def SystemStructurePerspective { }        // RequirementBody inside
viewpoint sysStruct : SystemStructurePerspective;

view def PartStructureView :> GeneralView {
    filter @Structure;
    render asTreeDiagram;
}

view vehicleView : PartStructureView {
    expose Vehicle::*;
    render asTreeDiagram;
}

abstract part def PowerSource;
#Safety part def SeatBelt;

part def Car {
    part seatBelt {@Safety;}
}
```

- `viewpoint def N { ... }` and `viewpoint n;` / `viewpoint n : Def;` are parsed;
  the body is parsed with the ordinary member parser (so `subject` / `require` /
  `doc` inside it already work).
- `view def N [:> Base] { ... }` and `view n [: Def] { ... }`; the body accepts
  `expose`, `filter`, `render` (and nested `view` / `viewpoint` / `doc`).
- `expose <ref>;`, `expose <ref>::*;`, `expose <ref>::**;` — `<ref>` is a
  qualified name. Stored per view as `{ ref, namespace, recursive }`.
- `filter @Name;` or `filter @A and @B;` — metadata names stored on the view.
- `render <name>;` — the rendering-usage name is recorded (not interpreted).
- `abstract` before `part` / `attribute` / `port` / `enum` / `requirement` /
  `state` / `action` / `item` sets `Element.isAbstract`.
- `#Name` before a definition/usage annotates it; `@Name;` inside a body
  annotates the enclosing element. Both append to `Element.metadata`.

Lexical: add `#` and `@` to the punctuation set.

## 3. Model additions

```ts
export type ElementKind =
  | ...existing...
  | 'viewpoint-def' | 'view-def' | 'view' | 'viewpoint';

export interface ExposeSpec { ref: string; namespace: boolean; recursive: boolean }

export interface Element {
  // ...existing...
  isAbstract?: boolean;
  metadata?: string[];
  exposes?: ExposeSpec[];   // on view / view def
  filters?: string[];       // on view / view def
  render?: string;          // on view / view def
}
```

`validate` resolves `view`/`view def` types like any other `typeRef`. Metadata
and expose refs are resolved lazily by the scope layer (section 4).

## 4. Scope layer (`src/views/scope.ts`)

```ts
export interface ActiveView { kind?: ViewName; allowed?: Set<string> }
export function activeView(model: SysmlModel, viewName?: string): ActiveView
```

- **Selection.** With `viewName`, pick the `view` usage whose `name`,
  `qualifiedName`, or `id` matches. Without it, pick the single `view` usage if
  exactly one exists; otherwise no view is active. View def `view def X` also
  supplies `expose`/`filter`/`render` inherited by the usage.
- **Kind mapping.** Resolve the view's definition and walk its specialization
  chain; the first matching name wins:

  | Name (standard library or project) | View |
  | --- | --- |
  | `GeneralView` | `bdd` |
  | `InterconnectionView` | `ibd` |
  | `ActionFlowView` | `activity` |
  | `StateTransitionView` | `statemachine` |
  | `RequirementView` (project extension) | `requirement` |
  | `bdd` / `ibd` / `activity` / `statemachine` / `requirement` | itself |

- **Allowed set.** Compute from `expose` and `filter`:
  - `expose X` / `expose X::**` → `X` and all descendants;
    `expose X::*` → `X` and its direct children (approximation, documented).
  - If `filter @A and @B` is present, keep only elements whose `metadata`
    contains every name.
  - `allowed` = union(expose subtrees) ∩ filter, or just the filter set when no
    `expose`, or `undefined` (no restriction) when neither is present.

`filterViewDescription(desc, allowed)` removes nodes not in `allowed` (keeping
synthetic `initial:` / `final:` / `control:` / `unresolved:` nodes) and then any
edge whose endpoint was removed; group members are pruned likewise.

## 5. View integration

- `selectView(model, view, opts?: { allowed?: Set<string> })` filters each view's
  output through `filterViewDescription`.
- `renderSvg(source, { view?, viewName?, theme? })`: when a view is active its
  `kind` overrides `view`, and its `allowed` set scopes the result.
- CLI: `--view-name <name>` (with `--view` still selecting the kind when no view
  is active).

## 6. Render

No new shapes are required. Abstract elements render their stereotype in italics
(`«block»` italic) via `shapes.ts`; metadata is not drawn (it drives `filter`).

## 7. Entry points

- Library: `renderSvg(source, { viewName })`, and `activeView` exported for
  tooling.
- CLI: `sysml2svg model.sysml --view-name vehicleView -o out.svg`.

## 8. Testing

- `parse-views.spec.ts` — view/viewpoint def/usage, expose forms, filter
  conjunctions, render, abstract, `#`/`@` metadata.
- `views-scope.spec.ts` — kind mapping through the standard bases; expose subtree
  and filter restriction; fallback when no view.
- `render-view.spec.ts` — a scoped view drops unexposed blocks from the SVG.
- `cli.spec.ts` — `--view-name` selects and scopes.
