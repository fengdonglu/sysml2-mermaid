# Design: v0.7 — More SysML v2 constructs

English only.

## Status

Approved for implementation planning. Builds on v0.6. Adds structural and
relationship constructs that real `.sysml` files use, so more models parse
without surprises.

## 1. Scope

1. **Items** — `item def` / `item x : T;` / `ref item`.
2. **Aliases** — `alias X for Y;`, resolved so references may use either name.
3. **Allocations** — `allocate A to B;`, `allocation def`, and
   `allocation n : Def allocate A to B;`.
4. **Connection / interface definitions** — `connection def { end ... }`,
   `interface def { end ... }`, plus `connection` / `interface` usages and
   `end` features.
5. **Port/item direction** — `in` / `out` / `inout` before a feature usage.

### Out of scope (deferred)

- Evaluating flow payload types; `connection`/`interface` *graphical* semantics
  beyond naming endpoints; `end` multiplicity expansion.
- `metadata def` bodies beyond the `#`/`@` annotations from v0.6.
- Conjugated ports `~T`.

## 2. Parser additions

Verified against the SysML v2 textual BNF and training models.

```sysml
item def Fuel;
item fuel : Fuel;
ref item driver : Person;

alias eng for Engine;

allocate torqueGenerator to powerTrain;
allocation def LogicalToPhysical { end logical : Logical; end physical : Physical; }
allocation a1 : LogicalToPhysical allocate torqueGenerator to powerTrain;

connection def PressureSeat {
    end [1] part bead : TireBead;
    end mountingRim : TireMountingRim;
}
connection ps : PressureSeat connect m.bead to w.rim;

interface def FuelInterface {
    end supplierPort : FuelOutPort;
    end consumerPort : FuelInPort;
}

part def Engine { in port fuelIn : FuelPort; out port drive : DrivePort; }
```

- `item` mirrors `part`: `item def N;` / `item n : T;`; `ref item n : T;`.
- `alias [<short>] Name for Ref;` — an `alias` element whose `typeRef` is the
  target reference.
- `allocate A to B;` → relationship `allocate`. `allocation [name] [: Def]` then
  either `allocate A to B;` or `{ ... }` (body parsed as members).
- `connection def N { ... }` / `interface def N { ... }` — definitions whose body
  accepts `end` features; `connection n [: Def] connect A to B;` and
  `interface n [: Def] connect A to B;` / `interface A to B;` (the latter already
  supported).
- `end [<mult>] [part|item|port|ref] name [: Type] [::> Ref];` — child element of
  kind `end`.
- Direction: `in` / `out` / `inout` may prefix `port` / `item` / `part` /
  `attribute` usages; stored on `Element.direction`.

## 3. Model additions

```ts
export type ElementKind =
  | ...existing...
  | 'item-def' | 'item'
  | 'alias'
  | 'connection-def' | 'interface-def' | 'end';

export type RelationshipKind = ... | 'allocate';

export interface Element {
  // ...existing...
  direction?: 'in' | 'out' | 'inout';
}
```

`validate`:
- Resolve `alias` elements: a reference whose name is an alias resolves to the
  alias target (so `alias eng for Engine;` lets `: eng` mean `Engine`).
- Resolve `allocate` endpoints like other relationships.
- Resolve `end`/`item`/`connection-def`/`interface-def` `typeRef`s normally.

## 4. Views

- **BDD** — `item-def` → `«item»`; a `connection-def` → `«connection»` and an
  `interface-def` → `«interface»` (both with their `end` features as rows);
  `item` usages appear as rows (like `part`). `allocate` relationships render as
  dashed edges (`kind: 'allocate'`).
- **IBD** — `item` usages become nodes (`«item»`) only if referenced by a
  connector; `allocate` renders as a dashed edge.

`ViewEdgeKind` adds `'allocate'`.

## 5. Render

`allocate` is dashed (like `dependency`). No new shapes; `«item»` /
`«connection»` / `«interface»` reuse the block shape.
