# Design: v0.4 — Language Server and VS Code extension

English only.

## Status

Approved for implementation planning. Mirrors the sibling `mermaid-opm`
packages (`packages/lsp`, `packages/vscode-opm`).

## 1. Scope

Two npm workspaces under `packages/`:

1. **`packages/lsp`** — a Language Server (`sysml-lsp`) reusing the core parser
   and model: diagnostics, completion, hover, and document symbols.
2. **`packages/vscode-sysml`** — a VS Code extension: syntax highlighting for
   `.sysml`, the language client, an SVG preview command, and an export command.

Out of scope: go-to-definition, rename, formatting, multi-file resolution.

## 2. `packages/lsp`

Mirrors `mermaid-opm-lsp` exactly in structure.

- `package.json`: name `sysml2-mermaid-lsp`, `type: module`, bin `sysml-lsp`,
  devDeps `vscode-languageserver`, `vscode-languageserver-textdocument`,
  `esbuild`, `typescript`, `vitest`, `@types/node`, and `sysml2-mermaid`
  (`file:../..`).
- `tsconfig.json`: `NodeNext`, `noEmit`, path alias `sysml2-mermaid` →
  `../../src/index.ts`.
- `vitest.config.ts`: same alias.
- `build.mjs`: esbuild bundles `src/server.ts` → `dist/server.js` with the alias
  and a `createRequire` banner.
- `src/server.ts`: the LSP wiring (connection, `TextDocuments`, initialize
  capabilities, configuration-driven diagnostics).
- `src/features/diagnostics.ts`: maps `renderModel(text).diagnostics` to LSP
  `Diagnostic`s (1-based → 0-based range).
- `src/features/completion.ts`: SysML keywords plus the model's element names.
- `src/features/hover.ts`: word under the cursor → the element's kind, type,
  doc/comment.
- `src/features/symbols.ts`: hierarchy of elements with mapped `SymbolKind`.
- `test/*.spec.ts`: unit tests for each feature plus a packaged-server smoke
  test (spawn `dist/server.js`, send `initialize`, expect capabilities).

## 3. `packages/vscode-sysml`

Mirrors `vscode-opm`.

- `package.json`: name `sysml2-mermaid-vscode`, publisher `fengdonglu`, engine
  VS Code `^1.94.0`, language id `sysml` for `.sysml`, grammar
  `syntaxes/sysml.tmLanguage.json`, commands `sysml.preview` and
  `sysml.exportSvg`, setting `sysml.diagnostics.enable`.
- `src/extension.ts`: starts the language client from the bundled
  `dist/server.js`, registers the preview (webview) and export commands using
  `renderSvg` from `sysml2-mermaid`.
- `syntaxes/sysml.tmLanguage.json`: keywords, types, relationships.
- `build.mjs`: bundles `src/extension.ts` (`external: vscode`) and the LSP
  `../lsp/src/server.ts` into `dist/`.
- `test/commands.spec.ts`, `test/contributions.spec.ts`: static checks on the
  extension source, `package.json` contributions, and the grammar.

## 4. Root integration

- `workspaces: ["packages/*"]` already exists in the root `package.json`.
- No root source changes are required; the packages alias the root `src/` in
  their test/build configs.

## 5. Testing

- LSP feature unit tests run in node with the alias to `src/index.ts`.
- The LSP smoke test builds `dist/server.js` (if absent) and speaks JSON-RPC.
- VS Code tests are static (source + JSON + grammar) — no VS Code host needed.
- `npm test` at the root continues to run only the root specs; each package has
  its own `npm test`.
