# Design: v0.9 — Parser ease-ins

English only. Builds on v0.8.

## Status

Approved for implementation planning.

## 1. Scope

Accept more real SysML v2 / KerML syntax so models parse without spurious
diagnostics, with minimal or no rendering impact.

1. **Modifier prefixes** — `variation`, `individual`, `ordered`, `nonunique`,
   `snapshot`, `timeslice`, `derived` (like `abstract`).
2. **Feature default values** — `attribute n = 20;`, `attribute m default = 10;`.
3. **Named binding** — `binding ab : AB bind a = b;` / `binding ab bind a = b;`.
4. **Port conjugation** — `port p : ~PortDef;`.
5. **Generic KerML/other declarations** — `metadata`, `concern`, `allocation`,
   `calc`, `function`, `predicate`, `class`, `assoc`, `connector`, `struct`,
   `datatype`, `rendering`, `expr` — parsed as `other` elements carrying their
   keyword (rendered as `«keyword»`).
6. **`exhibit`** — `exhibit state s : S;` (a usage) or `exhibit <ref>;` (a link).
7. **Requirement members** — `stakeholder`, `actor`, `invariant`,
   `assert constraint { … }`.
8. **View members** — `frame <ref>;`, and `satisfy <viewpoint>;` inside a view.

Out of scope: semantics/evaluation of any of the above; rendering `exhibit` /
modifiers beyond the stereotype text.

## 2. Model additions

```ts
export type ElementKind = ... | 'other' | 'stakeholder' | 'actor';

export type RelationshipKind = ... | 'exhibit';

export interface Element {
  // ...existing...
  modifiers?: string[];   // variation, individual, ordered, nonunique, snapshot, timeslice, derived
  defaultValue?: string;  // raw text after `=` / `default =`
  isConjugate?: boolean;  // `~Type`
  keyword?: string;       // the keyword for kind 'other'
  frames?: string[];      // view `frame` targets
}
```

## 3. Parser additions

- Prefixes: a `PREFIX` set handled before the declaration (set `modifiers`,
  consuming in any order); `abstract` keeps its own flag.
- Defaults: after a usage's type/multiplicity, accept `= expr` or
  `default = expr`; capture the expression text until `;` into `defaultValue`.
- `binding`: `binding [name][: Type] bind A = B;`.
- Conjugation: in a usage type position, an optional leading `~` sets
  `isConjugate` and is stripped from `typeRef`.
- Generic: for the keyword set, parse `keyword [def] Name [:> Base] [{ body } or ;]`
  (or a usage form) into an `other` element with `keyword`.
- `exhibit`: `exhibit [featureKeyword] name [: Type];` → a usage child; else
  `exhibit <ref>;` → relationship `exhibit` (source = owner).
- `stakeholder name : Type;` / `actor name : Type;` → child elements of those
  kinds (rendered as requirement rows).
- `invariant <…>;` and `assert [not] constraint { … }` → `constraint` children.
- `frame <ref>;` → append to the owner view's `frames`; `satisfy <ref>;` inside a
  view → relationship `satisfy` (source = owner).

## 4. Views / validation

- BDD/IBD/state/activity stereotype for `other` falls back to `el.keyword`.
- Requirement rows include `stakeholder` / `actor` children.
- `validate`: skip `defaultValue`; `other` elements resolve their `typeRef`
  normally; `exhibit` endpoints resolve; `stakeholder` / `actor` typeRefs resolve.

## 5. Testing

- `parse-easeins.spec.ts`: prefixes, defaults, named binding, conjugation,
  generic KerML/metadata/allocation, exhibit, stakeholder/actor/invariant, frame,
  satisfy-viewpoint.
- Existing 151 tests stay green.
